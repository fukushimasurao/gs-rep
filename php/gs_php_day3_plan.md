- 受講生：Day2でDB・PDO・XSS対策・SQLインジェクション体感まで終了済み

- AI活用：Day2で「聞く→生成→攻撃側」を経験済み。Day3では**AIに実装させる比重を上げる**フェーズ

## 方針

**「同じ型の繰り返しはAIに任せ、危険な操作と設計判断は自分の頭で」**

- detail.php → update.php → delete.php はCRUDとして同じ4ブロック構造の繰り返し。写経ではなくAI生成→差分確認に置き換えて時間を圧縮する
- 4時間分の内容を3時間に収めるため、**登録処理の復習は最小限**、**関数化は「自分のコードをAIにリファクタリングさせる」形**に変更し、時間を捻出する
- 新要素：**ペア/グループでの議論結果をAIに要約させ、Slackに投稿する**時間を設ける（考えを言語化する・他グループの意見を読む体験）

### コマ2 指導フロー詳細（delete.php：なぜGETよりPOSTか）

資料では、detail.phpへの遷移は`<a href="detail.php?id=...">`（GET）だが、削除は`<form method="POST">`にしている。この違いを講師が説明するのではなく、AIに質問させて回答を確認する形にする。

**生徒に投げさせるプロンプト（資料に記載済み）**
```
detail.phpへの遷移リンクはGET（<a href="detail.php?id=...">）で作りましたが、
delete.phpへの削除ボタンはPOST（<form method="POST">）で作るように言われました。
なぜ削除処理はGETではなくPOSTの方がいいのですか？
```

**講師用模範解答**

1. **GETは「安全なメソッド」という前提がある**
   HTTPの仕様上、GETは「サーバー側の状態を変えない取得専用の操作」として扱われる約束になっている。ブラウザやツールはこの前提を信じて動く。

2. **意図せず削除が実行されるリスクがある**
   - ブラウザの先読み（プリフェッチ）機能が、画面に表示されたリンクを事前に読み込んで削除を実行してしまう
   - 検索エンジンのクローラーがページ内の全リンクを辿るため、削除リンクを踏んでしまう
   - ブラウザの「戻る」で再度GETリクエストが飛び、二重削除が起きることもある

3. **POSTなら誤爆しにくい**
   POSTはフォーム送信という明示的なユーザー操作が必要なため、意図しない実行が起きにくい。データを変更する処理（INSERT/UPDATE/DELETE）はPOST、取得だけの処理（SELECT）はGETという原則に合っている。

**確認ポイント（AIの回答が浅い場合のフォロー）**
- 「なぜエラーにならずに実行されてしまうのか」まで踏み込めているか（PHP側はGET/POSTどちらでも$_GET, $_POSTで受け取れば普通に動いてしまう。防いでいるのは規約・実装側の使い分けであって、言語が自動で守ってくれるわけではない点を補足する）
- detail.php（GET）とdelete.php（POST）を対比させて、「データを変えるかどうか」で使い分けるという結論に落とし込めているか

**問いかけ例**
> 「もしdelete.phpもGETで作っていたら、select.phpに削除リンクを貼った瞬間、どんな事故が起きうる？」
> 「Googleのクローラーが自分のアプリを見に来たら、何が起きる？」

### コマ2 指導フロー詳細（WHERE忘れ危険体感）

Day2の「SQLインジェクション体感」に相当する、Day3の山場。

**Step1. 危険なコードを用意する**

```php
// ※学習用の危険コード。実際のコードでは厳禁。
$stmt = $pdo->prepare('UPDATE gs_an_table SET name = :name');
$stmt->bindValue(':name', $name, PDO::PARAM_STR);
```

**Step2. 実行してみる（練習用DB・バックアップ必須）**

- 1件だけ更新するつもりが、全件のnameが同じ値に書き換わることを確認
- DELETEも同様に試す：`DELETE FROM gs_an_table` をWHEREなしで実行→全件消えることを確認

**Step3. グループで議論**

問いかけ：
> 「実務でこれをやったら何が起きる？」
> 「WHERE句を書き忘れても、PHPはエラーを出さないのはなぜだと思う？」

→ Day2のSQLインジェクションは「攻撃者が悪意を持って」起こすが、WHERE忘れは「自分のミスだけで」全データを壊せる、という違いに気づかせる。

**Step4. AIで議論を要約してSlackに投稿**

【サンプルプロンプト】
```
【コンテキスト】
PHPの授業で、UPDATE/DELETE文のWHERE句を忘れると何が起きるかを学びました。

【依頼】
以下の議論内容を、Slackに投稿する3行以内の共有メッセージにまとめてください。
初学者にも伝わる言葉で、结论を最初に書いてください。

【議論内容】
（ここにグループで話した内容をメモしたものを貼る）
```

- 各グループがまとめたメッセージを`#gs-php-day3`（授業用チャンネル）に投稿
- 投稿後、他グループの投稿を読む時間を1〜2分取る（同じテーマでも表現の違いに気づかせる）

{% hint style="warning" %}
本番DBには絶対に試させない。練習用DBのバックアップ（SQLファイル）を事前に用意し、事故時はインポートし直せる状態にしておく。
{% endhint %}
