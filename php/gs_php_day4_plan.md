# Day4 講師メモ（3時間版）

## PHP授業 全5日間の概要

| Day | テーマ | 学ぶこと |
|---|---|---|
| Day1 | PHP基礎 | 変数・配列・関数・ループ、フォーム操作、ファイル保存 |
| Day2 | DB入門 | DB・テーブルの概念、SQL（INSERT/SELECT）、PHPからDB操作（PDO） |
| Day3 | CRUD | 詳細表示・更新（UPDATE）・削除（DELETE）、コードの関数化 |
| **Day4** | **ログイン機能** | **セッション管理、権限による処理の分岐、パスワードのハッシュ化** |
| Day5 | DBリレーション | テーブルの設計・正規化、JOINで複数テーブルを扱う |

## 前提

- 受講生：Day3でCRUD（詳細表示・更新・削除）と関数化まで終了済み
- 授業時間：50分 × 3コマ（計150分）※もともと4時間分（休憩10分×3回）の内容を、休憩10分×2回・3時間に圧縮する
- 宿題：ブックマークアプリ その4（ログインが必要なページ／不要なページの分岐）
- AI活用：Day2「聞く→生成→攻撃側」、Day3「同じ型の繰り返しはAIに任せ、危険な操作と設計判断は自分の頭で」を経験済み

## 方針

**「内容は削らず、AIで生成・比較・要約に置き換えて時間を圧縮する」**

- session01.php/02.php（SESSIONの初回体験）は、Day2のinsert.phpと同型で「AIスケルトン穴埋め→比較→自分で一部書く」に変更する
- login_act.php・ログインチェック処理も同様に、AI生成→授業資料と比較する形にし、写経量を減らす
- パスワードのハッシュ化パート（本編で最も詳細・長い箇所）は、**AIに構造説明を要約させる形を一度試作し、実際の見え方を確認してから採用を判断する**（下記「プラスアルファ②」参照）

## プラスアルファ②（ハッシュ化AI要約版・試作）

{% hint style="warning" %}
**試作段階。実際にAIの出力を見てから、この圧縮方針を採用するか判断する。**
{% endhint %}

現行資料のハッシュ化パートは、ハッシュ値60文字の構造（アルゴリズム識別子・コスト・ソルト・ハッシュ値本体の位置）を表と抜粋コードで詳細に説明している。この解説をAIに要約させ、講師は「なぜソルトが必要か」「なぜ毎回違うハッシュ値になるか」の2点だけ確認する形に置き換えられるか試す。

**生徒に投げさせるプロンプト（試作）**
```
password_hash()で生成されるハッシュ値の構造を教えてください。
$2y$10$92IXUNpkjO0rOQ5byMi.Ye4oKoEa3Ro9llC/.og/at2.uheWG/igi
という例を使って、どの部分が何を意味しているか、
初学者にも分かるように説明してください。
```

**確認ポイント（AIの回答で必ず押さえたい点）**
- ソルトの位置が固定である理由（`password_verify()`がソルト部分だけ抜き出して再ハッシュ化するため）
- 同じパスワードでも毎回ハッシュ値が変わる理由（ソルトが毎回ランダムに生成されるため）
- ハッシュ化（不可逆）と暗号化（可逆）の違い

**問いかけ例**
> 「もしソルトがなかったら、同じパスワードを使っている2人のハッシュ値はどうなる？」
> 「パスワードを『暗号化』ではなく『ハッシュ化』するのはなぜ？」

**判断待ちの論点**
- AIの回答だけで、60文字の位置（7-28文字目など）まで正確に説明できるか未確認 → 不正確な場合は講師補足が必須になり、圧縮効果が薄れる可能性がある
- 「試してみて微妙ならこのパートは手厚く残す」方針のため、次回この項目を実際にAIに試させてから最終決定する
