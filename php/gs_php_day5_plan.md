# Day5 講師メモ（3時間版）

## PHP授業 全5日間の概要

| Day | テーマ | 学ぶこと |
|---|---|---|
| Day1 | PHP基礎 | 変数・配列・関数・ループ、フォーム操作、ファイル保存 |
| Day2 | DB入門 | DB・テーブルの概念、SQL（INSERT/SELECT）、PHPからDB操作（PDO） |
| Day3 | CRUD | 詳細表示・更新（UPDATE）・削除（DELETE）、コードの関数化 |
| Day4 | ログイン機能 | セッション管理、権限による処理の分岐、パスワードのハッシュ化 |
| **Day5** | **DBリレーション** | **テーブルの設計・正規化、JOINで複数テーブルを扱う** |

## 前提

- 受講生：Day4でセッション管理・ログイン機能・ハッシュ化まで終了済み
- 授業時間：50分 × 3コマ（計150分）※もともと4時間分の内容を3時間に圧縮する
- 宿題：なし（自由課題。最終回のため）
- AI活用：Day2〜4で「聞く→生成→比較→自分で一部書く」の型を経験済み。Day5はこれの総仕上げとして使う

## 方針

**「概念の暗記より、AIに聞いて理解する体験を優先する」**

- 正規化（第1〜第3正規形）は、本編4時間版で一番時間を食っていたパート。フル段階展開（students/subjects/teachers/enrollments）は資料から削除し、**第1正規形の簡単な例1つ＋AIへの質問**に置き換えた。段階を踏んだ理解が必要な受講生には、質問プロンプトを膨らませて個別にAIと対話させる
- 多対多・中間テーブル（clubs/clubs_students/students）は、本編で扱うと時間超過しやすいため**プラスアルファに移動**。1対多との違いだけ本編で触れる
- 画像アップデート（既存画像の差し替え）は元から発展課題だったが、AI活用ボックス化してプラスアルファの目玉にする
- JOIN・INSERT・SELECT・画像アップロードの実装パートは、Day3/4と同じ「AIスケルトン穴埋め or 丸ごと生成→授業資料と比較」の型で統一し、写経量を削減する

## タイムライン

### コマ1（50分）― DBリレーションとJOIN

| 時間 | 内容 | スタイル |
|---|---|---|
| 5分 | 前回おさらい（Day4のログイン・ハッシュ化） | 講義 |
| 5分 | DB準備・SQLインポート（gs_db_class5） | ハンズオン |
| 10分 | リレーション・外部キーの概念 | 講義（users/contentsの例） |
| 15分 | 正規化（概念＋第1正規形の例） | AIに質問させて理解、講師は要点補足のみ |
| 15分 | JOINの書き方（employees/departments） | AI生成→比較 |

**AIの使い方：概念理解のために聞く（Day2コマ1と同型）**
- 正規化について、悪い例のテーブルを渡して「第1〜第3正規形がそれぞれ何を解決するか」をAIに説明させる
- 出てきた回答を全体で共有し、講師が「実務では第3正規形まで意識すれば十分」と整理する

---

### コマ2（50分）― アプリでのリレーション実装

| 時間 | 内容 | スタイル |
|---|---|---|
| 20分 | ログインユーザーidをセッション経由でcontentsに記録（insert.php） | AIスケルトン穴埋め→比較 |
| 20分 | select.phpでJOINして投稿者名を表示 | AI生成→比較 |
| 10分 | 1対多の整理・多対多の存在だけ紹介（詳細はプラスアルファへ） | 講義 |

**AIの使い方：実装はAIに任せ、SQLの構造は自分の目で確認**
- insert.phpは「user_idの取得」「INSERT文へのuser_id追加」の2箇所が変更点なので、そこだけ穴埋めさせる
- select.phpのJOIN文は丸ごとAIに生成させ、「なぜAS(エイリアス)が必要か」を問いかけて確認する

---

### コマ3（50分）― 画像アップロード機能・まとめ

| 時間 | 内容 | スタイル |
|---|---|---|
| 10分 | 画像アップロードの仕組み（enctype, $_FILES）の解説 | 講義＋var_dumpで確認 |
| 20分 | insert.php修正（画像保存処理） | AI生成→比較（拡張子チェック・uniqid・move_uploaded_file） |
| 10分 | detail.php / select.phpでの画像表示 | 写経（短いため） |
| 10分 | 課題説明・質疑応答 | 講義／自由 |

**画像表示だけ写経にする理由**
- `<img src="...">`を出力する数行のみで短く、「保存したものが表示される」という結果がすぐ見えるため、AI生成を挟むより自分で書かせた方が体験として強い

## 圧縮ポイントまとめ（4時間→3時間）

| 元の内容 | 対応 |
|---|---|
| 正規化：第1〜第3正規形をフル段階展開（学生管理システム例） | 第1正規形の例1つ＋AIに質問する形に圧縮 |
| 多対多・中間テーブル（clubs/clubs_students/students） | 本編から削除し、プラスアルファ①に移動 |
| insert.php・select.phpのJOIN実装を全部写経 | AIスケルトン穴埋め／丸ごと生成→比較に変更 |
| 画像アップロード処理（insert.php）を全部写経 | AI生成→比較に変更。表示部分のみ写経を残す |
| 画像アップデート（発展）が概要のみで具体性がなかった | AI活用ボックス化してプラスアルファ②として具体化 |

---

## プラスアルファ①（多対多・中間テーブル）

優先度：高（本編から追い出した内容のため、時間が余った受講生には積極的に案内する）

- 1対多と多対多の違いをAIに質問させる
- `clubs` / `clubs_students` / `students` の3テーブルをJOINで結合させる
- 参考：https://techlib.circlearound.co.jp/entries/db-table-many-to-many/

## プラスアルファ②（画像アップデート機能）

優先度：中

- `detail.php`に画像用inputを追加し、`update.php`で「送られてきた場合だけ差し替え、古い画像は`unlink()`で削除」する処理をAIに相談しながら実装
- 確認ポイント：新しい画像を送らなかったときに、既存の画像が消えてしまわないか

## プラスアルファ③（AIコードレビュー）

優先度：低（時間が余りすぎた場合のみ）

- 自分が書いたinsert.php（画像アップロード部分）をAIにレビューさせる
- 「拡張子チェックがない」「ファイルサイズ上限がない」等の指摘が出るはずなので、採用するか自分で判断させる
